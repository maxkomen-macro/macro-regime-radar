## Root causes and fixes (file:line at `b116f584`)

### 1. US day change (`4fd3ac53`)

- **Cause.** `QuoteHub._handle_tick` stored EODHD's `dc`/`dd` (`api/stream.py:627-628`). US trade frames carry `{s, p, c, v, dp, ms, t}` with no day change, so every US tick replaced the REST-seeded quote with `dc: null, dd: null`, and a newer REST row could not win back (`:660-663`). `_store_rest_quote` (`:650-672`) read `code, close, timestamp, change_p, change` and ignored `previousClose`.
- **Fix.** `_note_prev_close` keeps each US symbol's previous regular-session close, keyed to the New York session it applies to: a REST row from today's session gives `previousClose`; a row from an earlier session is itself that close (pre-open, a holiday, a name that has not printed yet). `_day_change` serves `dd = p − prev`, `dc = dd / prev × 100` (4 dp) on a US tick without `dc`, only when the kept close applies to the tick's own session; otherwise both stay null. **D1:** a US tick with `ms` `extended-hours` (or `closed`, a print outside the session) returns before touching the quote and is counted in `stats.us_ticks_held`; it no longer dates the feed either, so `live_quotes` reads the last regular print. Forex, crypto and REST rows keep EODHD's own figures. VIX keeps no previous close.
- **Consumers, checked.** Every one reads the served `dc`/`dd`, so none needed a code change: Macro tape (`MacroTape.tsx` `dayPctCell`/`dayDollarCell`), Single names and their live sort (`MarketsScreen.tsx:334-343`), the SPY/QQQ strip and the Dashboard glance tiles (`quote-ladder.ts` `quoteFor`, shared), Movers (`Movers.tsx:82`, `:97`: a name with `dc` now skips the candle fallback), the watchlist (`useWatchlistQuote.ts:109`). The Desk had no live-quote consumer before item 3c; its VIX tile now reads the same store.
- **Tests.** `tests/test_stream_day_change.py`, 8 tests, EODHD's documented shapes: pre-open (seed rows from Sep 30, a pre-market print held), in session (SPY, QQQ, AAPL day % against Sep 30's close), an in-session REST row carrying `previousClose`, after the close (four extended/closed prints held, the feed's last tick stays 15:59:59 ET), a holiday (Thanksgiving: the Wednesday close carries to Friday), a missing previous close (and one kept for the wrong session), FX/crypto pass-through, and raw JSON frames through `_run_feed`. Web: `quote-ladder.test.ts` adds the relay's US-tick shape.

### 2. FRED changes on month-stamped rows (`f5de30f8`)

- **Cause.** `api/db.py:649-686`: `credit_oas` took `latest − (newest row ≤ latest − 7 days)` over `raw_series`, which keeps one row a month dated the 1st (`src/utils/fred_client.py:71-77`). On the Sep row (dated 2026-09-01) the lookback reached the Aug row: "+49 bps 1W" was Sep 28 vs Aug 31. Every OAS "1W" did the same. The served `date` was the month stamp, so the strip tooltip (`TickerLive.tsx:81`) printed "Sep 01, 2026"; the signals header (`DashboardScreen.tsx:539`) printed the signals table's month stamp; `TenYearCard.tsx:3` called a 3-point history "90 daily closes"; `CurveMonitor.tsx:172-173` said "daily" on month-end points.
- **Fix.** `credit_oas` reads `desk_series` when it holds the series and is not behind the source watermark (DGS10; the HY OAS from 2023-09-25): the newest observation, the newest at or before seven calendar days earlier (at most ten back, else no change), a daily history and the observation's own date. Any other series (IG, BB, B, CCC) reads its previous month's row with `change_basis: "month_end"`, `change_from: "YYYY-MM"`, and its date from the source watermark when it falls in the newest row's month. `change_1w_bps` is now set only on a true week. The web reads `shared/rate-change.ts` everywhere a change prints: "1W" (title "Change over one week: Sep 28, 2026 against Sep 21, 2026") or "vs Aug month-end"; no basis, no label. Signals header: "5 signals · Sep 2026 print". TenYearCard: true daily closes ("daily closes, 90 days", or "one value per month" when the desk store is behind). CurveMonitor: "2s10s at each month-end", "FRED · month-end". Credit chart caption names each series' cadence.
- **Tests.** `tests/test_credit_oas_basis.py` (true week from the daily store; month-end for month-stamped series and never "1W"; a daily store behind the month row is not read; a hole wider than ten days prints no week; no desk store → all month-end; on the stored DB every label maps to its lookback). `rate-change.test.ts` maps each basis to its label. `test_accuracy.py`'s trace now expects the observation's true date.
